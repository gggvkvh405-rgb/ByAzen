## 1. WexSide — детальная проверка (основной объект)

Состав `Wexside-1.21.11-Main.rar` (оба `.rar` в репо — побайтово одинаковые, SHA-256 `de4088d3…`):
`WexSideSRC/` — 862 `.java` файла, ресурсы, `libs/` (5 jar), gradle-wrapper, `build.gradle`,
и готовый `wexside-client-1.0.0.jar` (958 классов).

Важная особенность: **исходники декомпилированы** (везде шапка `Decompiled with CFR 0.152`,
версия `1.0.0-recovered`, код использует intermediary-имена вида `net.minecraft.class_310`).
Логика и строковые константы при декомпиляции сохраняются, поэтому аудит полноценный.
Клиент, судя по всему, **нулл/кряк оригинала**: проверка лицензии вырезана, профиль
захардкожен (`ClientRole.USER`, имя из env-переменной `soezproject` либо строка
`"soezproject"` по умолчанию — см. `WexSideClient.java:259`). Это просто отображаемое
имя в меню, никуда не отправляется (сетевого кода в клиенте вообще нет).

### Что проверено в исходниках — всё чисто

- **URL в коде:** ни одного. Единственный URL во всём проекте — `https://maven.fabricmc.net/`
  в `settings.gradle` (репозиторий Gradle-плагина, легитимно). IP-адресов нет.
- **Сеть:** нет ни одного использования `HttpClient` / `HttpURLConnection` / `Socket` /
  `WebSocket` / `URL(` / OkHttp и т.п. Клиент полностью офлайновый — красть и отправлять
  данные ему буквально нечем.
- **Запуск процессов:** `Runtime.exec` / `ProcessBuilder` — нет.
- **Загрузка чужого кода:** `URLClassLoader` / `defineClass` — нет. JNI/`System.load` — нет.
- **Discord/Telegram/вебхуки:** упоминаний нет вообще.
- **Сессия/токены:** чтение сессии только для ника (`getSessionUsername()` для `usercache.wex`,
  легитимно). `accessToken`/`refreshToken` нигде не читаются.
- **Файлы браузеров/Discord:** нет обращений к `APPDATA`, `Local Storage`, `leveldb`,
  `Login Data`, `Cookies`, `.minecraft`. Все записи — только `config/wexside/*.wex`
  (конфиги, друзья, вейпоинты, макросы).
- **Пароли (`PasswordStore` / `AutoAuthModule` / `autoauth.wex`):** стандартный для
  чит-клиентов авто-`/register` + `/login` на серверах с AuthMe-подобной авторизацией.
  Пароль генерируется локально, хранится локально, в чат сервера уходит только сама
  команда `login <пароль>` (это назначение модуля), в свой чат пишется локальным
  клиентским сообщением (`ClientChat.send` → `sendMessage(..., false)`, на сервер не уходит).
- **Криптография:** только локальное шифрование конфигов (AES-GCM + SHA-256 + Base64
  в `EncryptedConfigIO`/`BinaryCodec`/`ConfigEntryCodec`, статический ключ захардкожен).
  Отправки ключей/данных нет (сети нет).
- **`ChestStealerModule`:** это «стиллер сундуков» — игровой чит-модуль (авто-лут
  предметов из сундуков), а не крадущий данные стилер. Название совпало случайно.
- **`sun.misc.Unsafe`:** только для нативных вершинных буферов рендера
  (`UnsafeAccess`/`NativeBuffer`/`GuiVertexBuffer`) — типовой приём чит-клиентов.
- **Буфер обмена:** только Ctrl+C / Ctrl+V в собственных текстовых полях клиента.
- **Микрофон/камера/скриншоты:** захвата нет. `AudioSystem` используется только для
  проигрывания кастомных звуков (`Clip`). Иконки микрофона в текстурах кодом захват
  не выполняют.
- **Миксины:** 46 записей в `wexside.mixins.json`, все 43 файла на месте 1-в-1,
  обычные хуки чит-клиента (пакеты, рендер, движение, HUD). Пакетный миксин только
  транслирует пакеты во внутреннюю шину событий.
- **Длинные строки/обфускация:** длинные литералы — только русские описания на русском
  в `\uXXXX`-виде. Подозрительных base64-блобов нет.
- **Посторонних файлов в `src/` нет:** только `.java`, `.json`, текстуры, шейдеры.
  Никаких `.exe/.dll/.so/.class`.
- **`gradlew.bat` и `gradle-wrapper.jar`:** стоковые (в jar только `org/gradle/*`).
- **`build.gradle`:** без подвоха — пустые `repositories {}`, обычный Loom `remap`,
  `Java 21`, `loom.layered { }` без маппингов (разработка против intermediary —
  именно поэтому декомпилированный код с `class_310` собирается).

### Проверка `libs/*.jar` — чисто

Все 5 jar — настоящий TwelveMonkeys ImageIO 3.12.0 (только пакеты `com/twelvemonkeys/*`,
посторонних классов нет). URL внутри — только служебные (github проекта, maven-схемы,
документация).

### Проверка готового `wexside-client-1.0.0.jar` — чисто, соответствует исходникам

- 958 классов, **все** в `ru.wexside.*`, посторонних пакетов/`.exe/.dll` нет.
- **Соответствие исходникам 1-в-1:** 958 классов = 862 топ-уровня + 96 вложенных
  (`$Inner`); классов без исходника — 0, исходников без класса — 0.
- Ресурсы jar = ресурсы `src/main/resources` + `MANIFEST.MF` + `LICENSE_wexside-client`
  (переименование `LICENSE` ровно как прописано в `build.gradle`). `wexside.mixins.json`
  идентичен исходному.
- Манифест — настоящий Loom: `Fabric-Loom-Version: 1.17.20`, `Fabric-Gradle-Version: 9.5.1`,
  `Fabric-Minecraft-Version: 1.21.11`, `Fabric-Loader-Version: 0.19.3` — совпадает
  с `gradle.properties` проекта.
- Строки внутри jar: URL — только метаданные картинок (Adobe XMP/EXIF), сетевых адресов
  нет; `getRuntime`/`exec` — 0; `getenv` — 1 (`soezproject`, совпадает с исходником);
  «stealer» — только `ChestStealerModule`.

**Вывод по WexSide:** вредоносного кода нет. Обычный (крякнутый) чит-клиент под 1.21.11.

## 2. Zenith — замечания

Активного стилера/ратника не найдено, но есть два момента:

1. 🔴 **`src/main/java/org/zenith/core/ImageEncoder.java` — мёртвый скриншотер.**
   Метод `atomicLong6()` делает скриншот **всего рабочего стола** через JNA
   (`User32`/`GDI32`, `BitBlt`), а `on23(url, bytes, ...)` POSTит multipart
   (поля `freinds`, `text`, файл `encrypted.bin`) на произвольный URL.
   **Вызывающих этот класс в исходниках нет (dead code)** — проверен весь `src`
   и рефлексия (`Class.forName` используется только в EventBus). То есть сейчас он
   инертен, но файл нужно **удалить до сборки**. Заодно проверь, что JNA вообще есть
   в зависимостях, иначе этот файл ещё и не скомпилируется.
2. 🟡 Сеть — легитимная по назначению, но знай куда идёт трафик:
   - `https://api.zenithdlc.org/mods/list/<ник>` — проверка, какие **локальные** аддоны
     разрешены нику (jar'ы не скачиваются, только список ID). Ник уходит на сервер.
   - `https://api.holyworld.me/v1/events` — опрос ивентов сервера HolyWorld.
   - `HeadlessBots` + `BotFeatureRegistry` — боты стримят своё состояние
     (позиция, здоровье, сервер) на backend. Это их штатная функция.
   - Discord RPC (`dev/firstdark/rpc`, аватарки `cdn.discordapp.com`) — Rich Presence.
   - `Runtime.exec`/`ProcessBuilder` — только открытие папки конфигов в проводнике
     и открытие t.me-ссылок (`rundll32 url.dll,FileProtocolHandler`), всё по клику юзера.
3. `libs/shaded-runtime.jar` (10 МБ) — ViaVersion + netty + Lua (`luaj`) + kotlin +
   Java-WebSocket + `dev/firstdark/rpc` + `dev/redstones/mediaplayerinfo`. Посторонних
   URL внутри нет (только доки/спеки). `baritone-meteor` и `zenith-addon-*` — штатные.

## 3. Kimiko — замечания

Активного стилера/ратника не найдено:

- Вебхуков/токен-грабберов/чтения браузеров и Discord-файлов — нет. `exec` — только
  открытие папки конфигов.
- 🟡 **Backend-адреса XOR-обфусцированы** (`rtx.kimiko.utils.net.Endpoints`), декодируются в:
  - IRC: `http://2.26.229.40:32115`
  - FunTime API: `http://2.26.229.40:32111/method/`
  - Party: `ws://2.26.229.40:32120`
  
  Функционально это обычные IRC/party/ивент-сервисы клиента (шлют ник, текст сообщений
  чата, uid), но трафик идёт **по голому HTTP на IP**, т.е. сообщения IRC не шифруются.
  Обфускация адресов сама по себе — анти-сниффер, а не малварь.
- 🟡 **`src/main/resources/META-INF/zk.dat` (6 МБ, энтропия 7.997 — шифротекст,
  сигнатура `ZKB1`) нигде в коде не используется** — ни одной ссылки, `Cipher`
  в проекте вообще не импортируется. Мёртвый груз; рекомендую удалить из ресурсов.
- `discord-rpc.dll` (x86/x64) — штатные библиотеки Discord RPC.

## Методика

Распаковка (`unrar`, собран из исходников + `unzip`), полный перебор строк/URL/IP,
поиск по сигнатурам (webhook, token grab, leveldb, `Login Data`, `Cookies`,
`URLClassLoader`, `getRuntime().exec`, `TargetDataLine`, JNI и т.д.) с ручным разбором
каждого срабатывания в контексте, сверка классов jar с исходниками, проверка манифестов,
миксинов, ресурсов, wrapper'а и `libs/`. Декомпиляция не требовалась: WexSide уже идёт
с CFR-исходниками, остальные проверялись по коду и строкам.
